# 画语 Canvas

一个运行在本机的单用户设计平台。Next.js App Router、React 和 TypeScript 提供统一工作台：左侧对话，中间设计预览，右侧编辑画布、内容和独立对象。Agent、文件存储和 PDF 渲染继续由同一 Node 进程中的 Express 服务负责。

内置「商品推广设计」「杂志海报」「菜单设计」「水彩绘本」「品牌 Logo」五个 Skill，也支持自由创作和导入自己的 Skills。对话与图片模型可以分别接入不同服务商。

## 快速启动

需要 Node.js 22+ 和 npm。在项目目录执行：

```bash
npm install
cp -n .env.example .env
npm run dev
```

打开 `http://127.0.0.1:4320`。`cp -n` 保留已有 `.env`；首次使用时，示例配置中的 Key 留空即可进入演示模式，不调用真实 API。使用 Docker 沙箱时还需要启动 Docker，详见下方「沙箱与脚本」。

`npm run dev` 启动 Next.js 开发模式，前端支持热更新；修改 `server/` 中的后端代码后需重启进程。生产模式先执行 `npm run build`，再执行 `npm start`。两种模式默认均使用端口 4320，不需要额外启动 API 服务。

## 使用流程

1. 上传、拖入或在输入框粘贴参考图片，支持多选和连续粘贴，最多 8 张，单张不超过 10 MB / 2500 万像素。参考图按加入顺序显示，发送后附在对应消息里，输入区清空；失败则保留。
2. 默认使用「可编辑设计」。右侧「画布」设置名称、宽高、像素或毫米单位；在左侧说明用途、风格和每张参考图的用途。演示模式可以手动创建设计稿；真实 AI 设计需配置模型。
3. AI 设计完成后直接显示在主画布。右侧「内容」核对文字和价格；「对象」添加或选择文字、图片、Logo 和色块，调整文字、颜色、坐标与尺寸。保存后更新预览。
4. 继续对话可局部改字、改价或调整排版。每个成功 AI 结果保存完整快照，也可点击画布上方「保存版本」，从底部恢复旧版本。
5. 顶部「下载作品」下载当前画布上的设计稿或图片，支持 PNG/JPG RGB、RGB PDF、CMYK PDF。设计稿有未保存修改时，先保存再按该版本导出；待核对内容会阻止下载。
6. 选择「图片创作」可使用原有整图生成工具。已有图片通过「查看历史图片版本」浏览、下载，或点击「以此图创建设计稿」作为整体图片导入。独立设计稿已有内容时不覆盖。
7. 左侧「技能库」管理本轮素材选择和创作技能；「模型设置」沿用本机中转站和模型配置。历史会话、任务取消、草稿恢复继续保留。

只想讨论方案时，可以直接说明「先讨论，不生成」。运行中的任务可点击「停止」；已保存结果保留，已提交给服务商的请求不保证停止执行或计费。服务重启后，未完成任务标记为中断，不自动重试。

原生页面仍保留在 `/legacy/`，其中的技能导入、商品原图对照等辅助工具尚未改写成 React；它与新工作台共用原有数据和接口。必要时可用 `npm run start:legacy` 启动原版，不需要 Next.js 构建。旧 `/design.html?session=...` 链接会跳转到新工作台的同一会话。

## 对话确定图片尺寸

切换「图片创作」，可以说「先确认宽 585、高 1080 像素，暂不生成」，再发送制作要求；也可以在同一条制作消息中指定尺寸。助手通过 `set_image_target` 记录明确目标，输入框上方显示尺寸、宽高比和适配方式，后续改图沿用。比例可自由填写，例如 1:1、9:16、21:9、7:11，也可在后续对话随时更换。只说明「13:24」则记录比例，当前对应输出 832 × 1536 px；准确像素与只指定比例分别保存。宽高顺序或物理单位不清楚时应先澄清。设置入口可手动调整或取消，刷新后保留，选择历史图片版本恢复该版本的目标，既有文件保持不变。

「尺寸与比例」同时提供生成精细度和原生分辨率。默认 `high`；可选快速预览 `low`、标准 `medium`、自动，以及 GPT Image 2.5 支持的 `xhigh` / `max`。分辨率可按目标尺寸匹配，或选择最高 2K / 4K；助手也可通过 `set_image_generation` 根据对话记录，跨轮改图、刷新和历史版本恢复均保留设置。选择高清分辨率前需先确定尺寸或比例，不擅自固定画幅。

GPT Image 2 系列会将匹配后的原生尺寸直接传给 Images 生成和编辑接口的 `size`，不再一律请求 `auto`。请求遵守每边 16 的倍数、最长边 3840、总像素 655360–8294400、原生宽高比 1:3–3:1 的约束；超过 3686400 像素标记为实验输出。13:24 的 4K 档请求并交付 2080 × 3840 px；若另行要求准确交付 585 × 1080 px，则请求高清原图后缩小交付，同时保留原图下载。方形等比例因总像素限制不会达到 3840 × 3840；设置面板始终展示实际预计像素。其他模型在自动分辨率下仍沿用服务商配置的 `IMAGE_SIZE`（默认 `auto`），不承诺未接入的高清能力。

返回后平台检查实际尺寸：相同比例等比缩放；不同比例默认完整保留画面并留边，用户明确选择后才居中裁切，始终不拉伸。交付目标每边 16–8192 px，总计不超过 2500 万像素；放大像素不会新增原图细节。画布分别展示请求尺寸、模型实际返回尺寸与最终交付尺寸；服务返回尺寸不符会明确提醒。可单独下载适配前原图，原图不是额外设计版本。默认 PNG/JPG 原始像素下载使用适配后的文件。上游拒绝参数时不自动降档或重新生图。

此功能保证交付文件的尺寸和比例，不代表图片模型原生支持任意尺寸，也不保证构图、文字或产品识别质量。对话理解依赖所配置的模型；演示模式仅验证手动设置及本地适配，不理解对话。可编辑设计模式的画布设置独立于整图目标，本轮未新增其对话改尺寸工具。验证入口为 `npm run test:image-target` 和 `npm run test:image-target-ui`，后者使用生产构建与模拟模型。

## 品牌 Logo 与透明 PNG

在技能库选择「品牌 Logo」，工作台自动进入图片创作。默认让准确店名本身参与设计，与人物/符号、边框及装饰形成完整标志：字形、色彩、比例和留白由同一图片模型统一设计，交付图片内已包含店名，不再后加一份普通文字。可上传多张真人照片制作 Q 版人物，也可描述抽象图形、品牌符号或吉祥物；不固定使用人物风格。明确提供准确店名、辨识特征及需要保留的内容，例如：

```text
参考我的照片做一个 Q 版品牌人物，保留发型，加黑色圆框眼镜。
店名准确为「菜火生」，把字形、配色与人物、边框统一设计成完整品牌 Logo，交付透明底 PNG。

在上一版完整 Logo 上把店名改为「菜火生小馆」，尽量保留人物特征和整体风格。
```

完整 Logo 通过现有生图/编辑接口创建，默认请求 `background=transparent` 和 PNG；具体模型与中转站必须实际支持该参数。一体化 Logo 的文字也在图片中，改店名、字形或人物细节都属于图片编辑，可能产生图片模型费用，不能承诺其他像素完全不变。用户明确只要纯图形时按其要求创作；必要店名缺失时先确认，不编造。生成的中文可能出现错字、漏字，需要用户逐字核对。

系统在尺寸适配前检查原始返回图片，适配后再次检查：必须存在可见主体、全透明像素及透明边缘。白底、模拟透明的棋盘格、仅有不透明 alpha 通道或全透明空图均不会保存为透明 Logo。失败记录本轮尝试，不自动重试、不静默改用白底或更换模型。像素检查不能代替文字准确性、人物相似度、抠图边缘或视觉设计质量的人工核对。

只有明确要求「店名单独可编辑」或继续修改此前分层稿时，才使用 `compose_logo`：用独立透明图形与准确店名生成分层组合稿。上下组合、左右组合共用现有字体排版引擎，分层稿只改店名不调用生图；一体化设计与源文件分层是不同需求。新组合追加页面并保存完整版本，已有页面保留；更新此前的分层 Logo 页面保留对象 ID、位置及样式，并遵守锁定、revision 冲突和取消保护。将旧分层稿改为一体化设计会生成完整新图并保留旧稿，不把简单压平旧稿视为重新设计。

画布上方「图片组合」可直接选择或上传底图和透明 Logo，拖动 Logo 或输入百分比位置、区域宽高、不透明度，并选择完整显示或居中裁切。保存追加一个图片版本，不调用聊天或图片模型。底图尺寸和原始素材保留，高清组合图可从画布下方下载，也支持现有 PNG、JPG、PDF 下载。重新打开「调整组合」会载入原底图和参数，避免重复叠加旧 Logo；白底或模拟透明的图片会被拒绝。

右侧「画布」可切换透明背景，PNG 下载保留透明通道；预览棋盘格不会写入文件。JPG 使用白底。普通 PDF 保留独立文字，人物图片仍为位图。

主工作台下载面板另提供 **SVG、EPS、AI 矢量 Logo**；普通 RGB PDF 可勾选「矢量 Logo PDF」。一体化整图中的图形和字形一起通过 VTracer 描摹为实际曲线路径；分层稿的独立文字转轮廓，不嵌入 PNG、不依赖接收方字体。SVG、EPS、AI 和矢量 PDF 使用同一组路径、位置与裁切边界，仅导出当前页。导出是只读操作，不覆盖原图、可编辑文字或版本；导出本身无需再次生图。旧版工作台的下载选项仍为 PNG/JPG/PDF。

矢量描摹是近似转换：最多 32 色，输入最长边按需缩至 768 像素；柔和透明边缘以 50% alpha 阈值转换为实边，细节、渐变和颜色可能变化。点击「预览并检查」后先核对轮廓、眼镜及颜色，再勾选确认下载；接口也要求显式确认。透明孔洞和不透明白色细节分别保留，棋盘格不会写入文件。复杂照片应先生成简洁的 Logo 图形，再导出矢量格式。每页最多描摹 12 张不同图片、12,000 条路径、250,000 个路径段；描摹运行在工作线程中并设超时，失败不会回退为嵌入位图或自动调用收费模型。

AI 是按公开 Illustrator 7 规范生成的旧版 PostScript 路径格式，具有独立可执行的 EPS prolog，**不是现代 Illustrator 原生编辑格式，也不是改后缀的 PDF**。已用独立 Ghostscript 渲染验证 AI/EPS 与 SVG 画面一致，但尚未经过本机 Illustrator 打开验证。矢量输出当前为 RGB；CMYK、ICC、出血与裁切线继续使用现有普通印刷 PDF。需要改字请保留平台原稿，转轮廓后的字形可作为路径编辑。实际包装印刷所需的尺寸、颜色和格式由印刷方确认；本功能不提供跨项目品牌库。

聚焦验证使用临时数据、真实 SDK 配合模拟模型响应，不调用收费模型：

```bash
npm run test:logo
npm run test:vector
# 先完成生产构建，再验证主工作台
npm run build
PLAYWRIGHT_EXECUTABLE_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' npm run test:logo-ui
```

浏览器验证产物保存在 `test-results/logo/`，包含桌面/手机截图、描摹预览及 PNG/JPG/SVG/EPS/AI/矢量 PDF。可选独立 PostScript 验证：在临时目录安装 `@jspawn/ghostscript-wasm@0.0.2`，设置 `GHOSTSCRIPT_WASM_DIR` 为该包目录后运行 `node scripts/verify-vector-postscript.mjs`，产物写入 `test-results/vector/`；此渲染器不属于应用依赖。真实模型对人像的还原和当前中转站对透明背景的支持需另行验收。

## 通用可编辑设计稿

设计稿已接入主工作台，聊天、预览、属性、版本和下载使用同一文档及 revision。右侧「画布」可以手动新建，也可由 AI 创建。已有图片通过「以此图创建设计稿」作为独立图片对象导入；已有设计稿不会被覆盖。支持自定义像素或毫米尺寸；文字、图片、Logo 和色块分别保存。位置与尺寸使用当前画布单位，字号使用 pt；切换单位保持原有物理大小。

主工作台的「可编辑设计」模式使用现有对话模型创建单页或多页结构化设计；已有稿件可继续描述改价、改字或局部排版。工具分别创建、按 ID 合并对象或更新内容字段，本模式不调用图片生成工具。需要整图生成时切换「图片创作」。执行记录和结果保存在同一会话中。演示模式不会调用真实模型或伪造 AI 设计结果。

内容字段记录名称、值、素材来源和核对状态，文字对象通过 `bindingId` 关联。右侧「内容」与对象文字属性双向同步；画布上方「核对内容」可直接打开面板。识别不清的内容标为待核对，用户确认前禁止导出。模型识别可能出错，菜名、价格、品牌信息仍需用户核稿。参考图在接受本轮请求后清空勾选并归入消息，不会重新放回下一轮附件。

AI 提交在保存前检查文档结构、素材归属、缺字、越界和文字溢出。失败返回具体问题，不保存半份稿件；待核对内容可以保存预览。成功结果自动存为设计版本，未保存过的修改前稿件也留快照；其他窗口修改造成的 revision 冲突会拒绝覆盖。取消后尚未提交的设计不会写入，已经保存的结果和历史版本保留。

顶部「下载作品」始终对应当前画布内容。设计稿 PDF 使用画布实际尺寸；图片模式可以直接下载原图，无需创建文档。文件格式与色彩模式分别选择，PNG/JPG 使用 RGB，PDF 可选 RGB 或 CMYK。转 PDF 或放大不会补充原图细节；原尺寸图片 PNG 保留原文件。下载不增加会话的图片版本或参考图。原生页面的图片下载工具仍提供临时 PDF 页面尺寸设置。

素材选择来自当前会话已有的真实图片，上传素材与旧的 PNG 作品继续保留。设计稿的草稿、保存版本和恢复操作独立于原来的图片版本；不同窗口写入发生冲突时会提示刷新，避免覆盖新稿。未同步内容保留在本机草稿中；尚未完成本机备份时，离开页面会提示。

下载支持 PNG/JPG RGB、带嵌入字体的 RGB PDF，以及实际转换颜色、嵌入四通道 ICC 的 CMYK PDF。预览和 PDF 共用排版结果；文字溢出、缺失素材、字体不支持的字符会阻止下载，低清图片给出有效分辨率提示。普通位图不会因放入设计稿或转成 PDF 自动获得文字图层或矢量细节。

当前支持最多 20 页。画布上方「页面」列表切页，「新增」「复制」「←」「→」「删除」操作当前页；右侧属性、对象和尺寸跟随当前页。复制页面会复制绑定内容，后续修改副本不会改动原页；共同使用同一字段的其他页面仍同步更新。页面操作和内容修改共用整册草稿，保存版本与恢复都作用于完整文档。

### 画布直接编辑与撤销

- 在画布点击文字、图片或色块，拖动移动；拖动四角调整对象尺寸。文字调整的是文本框，字号保持原值；图片按已有适配规则显示。按住 Shift 等比例缩放，移动时按住 Alt 临时关闭吸附；吸附包括页面与其他对象的边缘和中心。画布工具栏可对齐到页面左/中/右及上/中/下。
- 选中对象后点击画布上方「编辑属性」可定位属性面板，拖动时保持当前视野。手机可通过「返回画布」继续操作；定位面板不会自动弹出文字键盘。四角的实际操作区域为 32 屏幕像素，向对象外侧扩展，小对象的中间仍可拖动。对象列表独立滚动，避免属性被长列表推到下方。
- 画布获得焦点后，方向键微调（像素页 1 px、毫米页 0.25 mm），Shift 加速 10 倍；Delete/Backspace 删除选中对象，Esc 取消当前拖动或清除选择。手机使用同一对象坐标与触摸操作，拖动取消不会写入草稿。
- 画布工具栏的撤销/重做，或非输入框内的 `⌘/Ctrl Z`、`⌘/Ctrl Shift Z`（Windows 也支持 `Ctrl Y`），覆盖属性、内容绑定、对象增删、页面复制/删除/排序与画布操作。一次拖动为一步，输入框一次聚焦期间连续输入合为一步。新编辑清空重做分支；手动保存和保存版本不清空历史。历史最多 100 步且受 12 MB 序列化估算上限约束，当前窗口内有效；切换会话、重新载入、恢复历史版本或接受 AI/外部文档会重置。
- 画布按独立对象即时绘制，文字的字形、换行和基线由现有服务端排版引擎计算，使用与 PNG/PDF 相同的字体。位置变化复用字形；改字、字号或文本框尺寸后重新排版。草稿字形接口只读，不保存文档、图片或版本。未保存的新页面也可直接预览和编辑。
- 修改停顿 1.2 秒后自动保存当前稿，保存期间仍可编辑，回执不会覆盖后续输入，也不会打断连续输入的撤销分组。点击「保存修改」或 `⌘/Ctrl S` 可立即保存，下载、AI 提交与保存版本会等待后台保存并保存剩余修改。自动保存不创建历史版本。刷新后的撤销历史恢复、多选和旋转尚未提供。

### 图片替换与图层

- 在右侧「对象」中选择图片或 Logo，「替换图片或 Logo」可选择本会话素材，或「上传新图并替换」。保留对象 ID、位置、尺寸、完整显示/居中裁切及出血设置；原素材保留，旧版本仍使用原图。替换上传不改变聊天附件或当前图片版本的选择，即使已选满 8 张参考图也可使用。
- 「复制对象」生成稍微偏移的可编辑副本；画布获得焦点时也可用 `⌘/Ctrl D`。绑定文字会复制对应内容字段及其来源、核对状态，修改副本不改原文。副本显示且未锁定，每页最多 300 个对象、整册最多 1000 项内容。
- 图层列表从前到后显示，对象属性支持「置顶」「上移一层」「下移一层」「置底」。列表的锁和眼睛按钮分别控制锁定与显示，隐藏、锁定后仍能在列表中选择。
- 锁定阻止画布移动、缩放、键盘删除、属性编辑与 AI 改写。共享文字只要有一个绑定对象锁定，内容面板与 AI 都不能改其文字；核对状态仍可确认。可随时解锁、切换显示或复制出可编辑副本。明确的整页删除、尺寸/单位调整和版本恢复仍作为页面、文档操作执行。
- 隐藏对象保留在文档、撤销、本机草稿和版本中，但不进入画布、吸附、PNG/JPG、普通 PDF、CMYK PDF 或印刷检查。只绑定到隐藏文字的待核对字段暂不阻止导出；恢复显示后继续核对。未放置的待核对字段仍阻止导出。

### 自动保存与本机草稿

- 每次已提交的编辑会立即排队写入本浏览器的 IndexedDB，不包含图片副本。各窗口独立保存，成功同步后清理当前窗口的备份；不会清理其他窗口尚未同步的稿件。浏览器清理站点数据或更换浏览器后，这些本机草稿不可用。
- 刷新、重新打开项目或切换会话后，若有未同步的稿件，画布上方显示保存时间、名称和恢复入口；多份草稿可选择。恢复包含整册内容、当前页与对象选择，支持暂时不满足导出条件的内容，例如尚未输入完成的名称。恢复历史撤销步骤尚未实现。
- 网络或保存失败时保留编辑能力，显示本机备份状态、重试入口与 JSON 草稿下载；重新联网时重试。浏览器存储不可用时明确提示，不能把当前窗口内的修改显示为已备份。关闭时若备份尚未完成，保留浏览器离开提醒。
- 后台和手动保存串行执行，使用原始 revision 检查；其他窗口已经更新时暂停自动同步，保留本地内容。恢复旧 revision 的草稿也暂停同步，不自动合并或覆盖最新稿件；可下载 JSON 备份、重新载入最新稿件，原本机草稿仍可再次恢复。JSON 备份保留文档及素材引用，不是包含图片文件的独立项目包，暂未提供重新导入入口。
- 自动同步请求超时为 15 秒；回执丢失后，重试只有在服务端内容与提交内容完全相同时才确认保存成功。保存版本仍需明确点击，自动保存不会占满版本记录。

画布上方「清单自动分页」可手动录入 `名称 | 值 | 说明`（每行一条，后两项可留空），选择 1–3 栏、10–36 pt 字号及每页 Logo。结果追加到整册末尾，重复标题与原始 Logo；按实际字体测量整条换行，不拆条、不静默缩小或遗漏。单条内容放不下、缺字、超过 20 页或对象/内容上限时不保存分页结果。AI 也可调用同一分页能力，素材来源与待核对状态保留。此能力覆盖清单、菜单、价目表，复杂杂志和自由图文的自动排版仍待后续开发。

「下载作品」的 PDF 支持整册、当前页及自定义页码（例如 `1-3,5`），按文档顺序导出；PNG/JPG 下载当前页。校稿问题显示所属页面，点击可跳转。专业软打样和 PDF/X 符合性认证仍属后续阶段。直接导入位图只是增加图片对象；要获得独立文字，需通过 AI 参考识别重新排版或手动录入。

### 印刷下载与检查

「下载作品」提供「线上图片」「普通 PDF」「打印 PDF」三个预设，文件格式和色彩模式仍可分别选择。打印 PDF 默认使用 RGB、300 PPI，按实际素材分辨率检查清晰度。整张图片自动按原始可用像素换算页面毫米尺寸，不固定 A4 或海报尺寸；有模型原图时优先使用原图，保持已有裁切和留边。自动尺寸为 `原始像素 / PPI × 25.4 mm`，可明确切换为自定义尺寸；超过素材清晰度时阻止高清打印下载，并列出需要的像素。设计稿则沿用各页成品尺寸，并为图片对象读取原始素材，独立文字、图形继续保留矢量。页面范围支持整册、当前页和自定义页码。

普通 PDF 与默认打印 PDF 均不进行 CMYK 颜色转换，可交给接受 RGB 文件的印刷方按设备处理。按印刷方要求选择 CMYK 后，需要明确选择或导入目标 ICC；只有服务器通过 `STUDIO_CMYK_PROFILE` 配置的默认输出条件会自动选中，不会自动套用内置验证配置或任意已导入配置。面板提供一键切回 RGB。内置 `Chemical proof` 仍可手动选择用于技术测试，面板、检查报告与下载状态均标明测试用途；这不代表印刷色彩匹配，正式印刷需按实际设备和材料选择 ICC 并打样。CMYK 输出为普通 PDF，不标记为 PDF/X-4。

- 清晰度可选 72/96/150/300/600 PPI。图片按成品尺寸计算输出像素并记录密度信息；PDF 保留文字和图形矢量，仅对超过目标分辨率的位图降采样，不放大低清原图。图片下载上限为 2500 万像素。
- 四边出血可设为 0–20 mm，可选裁切线；写入成品 TrimBox、出血 BleedBox 和含标记的 MediaBox。开启裁切线时，在出血区域外另加 8 mm 标记边距。背景默认延展；对象属性中的「印刷时延展到出血区」可单独启用贴边色块、图片的延展。仅延展对象触及的边，图片需为居中裁切填充，按原图比例重新裁切，不复制或拉伸边缘像素；Logo 和未勾选对象保持原样。旧稿无需迁移，原有 API 默认仍只延展背景，下载弹窗可切换这两种规则。
- 可选择服务器默认 ICC，或导入印刷方的 CMYK 输出 ICC/ICM。导入上限 4 MB、本机最多 20 份，内容相同自动去重，保存在数据目录的 `print-profiles/`。检查文件头、转换标签、实际转换结果及嵌入 ICC 一致性；不接受 RGB 配置、损坏配置或静默回退结果。
- 纯黑文字可选择保持 K100 或全部按 ICC 转换；裁切线固定使用单黑。普通 CMYK 文件允许灰度透明蒙版。
- 「检查文件」显示所选版本、页数、各页成品/输出尺寸、字体、ICC、有效分辨率、贴边内容和文字安全距离。安全距离可设为 0–20 mm，默认 3 mm，仅用于检查和辅助线，不改变作品。延展后重新计算图片有效 PPI，并提示核对裁切主体；已勾选延展但使用完整显示的图片会阻止此印刷规则的下载。缺字、文字溢出、缺图、待确认内容和超限也阻止下载；印刷提示需核对确认后继续。默认印刷检查值为 300 PPI，可随输出目标调整。
- 检查后可按所选下载页面查看「裁切预览」，切换成品线、出血线及安全区域的显示。这些辅助线不进入文件，下载设置中的裁切标记单独输出。预览使用与 PDF 相同的出血几何与图片裁切规则，但以 RGB 显示，不是色彩软打样。检查提示的「定位对象/内容/页面」会返回对应编辑面板；可导出含 revision、页面、ICC 和设置的 JSON 检查报告，修改后需重新检查。
- 印刷文件生成后重新读取，核验页面框、嵌入字体、CMYK 图形/图片及目标 ICC；失败不返回文件。此检查是平台承诺项检查，不能替代独立 PDF/X-4 符合性验证或印刷方实机打样。
- 下载按请求开始时的文档快照生成，文件名包含 revision/版本、页码和色彩模式。失败保留当前设置；关闭下载弹窗后可继续编辑，已开始的下载不随其后的编辑改变内容。

### 字体与色彩配置

- 使用允许嵌入的单个 TTF/OTF 字体文件，可通过 `STUDIO_FONT_FILE` 指定。macOS 默认尝试系统 Arial Unicode，Linux 默认尝试单文件 Noto 中文字体；字体不存在时会明确提示，不使用缺字字体静默代替。
- 可用 `STUDIO_CMYK_PROFILE` 指定实际印刷方要求的 CMYK ICC 文件。未配置时使用 sharp 内置的 `Chemical proof` 配置，仅用于技术验证；界面会展示配置名称，不能据此承诺适合任意印刷设备。
- 当前没有通过 PDF/X 验证，下载文件不标注 PDF/X 认证。
- 设计稿保存在数据目录下的 `documents/`，按会话关联；现有会话和图片数据不需要破坏性迁移。

## 商品推广设计

### Skill 提供方法，Agent 决定画面

上传商品实拍，说明推广用途、想传达的感觉和具体要求即可。Skill 提供设计方法、参考资料和商品真实性要求；Agent 根据本轮需求决定主题、人物或场景、构图、光影、色彩、图文关系及画幅。

商品推广图可以是完整宣传海报、无新增文字的商品展示图、上手佩戴广告或生活场景图。是否添加文字取决于传播目的，内部创意主题不会自动变成画面标题，也没有固定的场景、配色、标题位置或卖点数量。

设计判断从商品的吸引力出发：餐饮想表现诱人时，结合菜品的色泽、纹理和实际冷热状态；珠宝想表现贵气时，结合真实外观、光泽、细节与佩戴关系。行业例子用于启发，不绑定模板；用户希望清爽、平价或年轻时，采用相应表达。同一商品也会因受众、用途和本轮诉求变化。整图没有明确尺寸时，不再把平台初始的 1080 × 1440 参考尺寸自动写入生图提示；确认过的自由比例、高清设置和本轮主动选择的画幅继续生效。

可编辑设计也支持通过对话指定尺寸，例如“按宽585、高1080 px 设计”。新建时直接采用目标宽高，已有稿件通过 `apply_design_changes.pageSize` 同时调整当前页尺寸与布局，其他页面保留；改单位会换算原有对象坐标并保留实际大小，文字字号仍用 pt。尺寸与排版在同一次校验、版本保存中生效，溢出或冲突时不保存部分修改。

例如：

```text
基于这件商品做一张社交平台推广图，用画面体现轻盈、自然的感觉。

做成女性上手佩戴广告，用姿态和光影表现高贵感，画面不要新增文字。

保留这一版的场景、光线和排版，只把主标题改成「今日好心情」。
```

提出「单调、换个感觉、重新设计」等整体反馈时，Agent 应重新考虑视觉表达；明确要求局部修改时，则保留指定内容。商品依据和用户确认过的规范持续有效，Agent 上一轮自行选择的风格只作为参考。

### 商品依据与连续修改

- 商品资料区分「用户提供」「视觉观察」「待确认」。品牌、材质、工艺、价格、折扣和功效需要依据，缺失信息不编造。
- 连续修改将 `sourceId` 指定的完整海报作为实际编辑底图，商品实拍作为辅助参考同时传给图片接口，并记录真实传入的图片 ID 和父版本关系；不会用商品照片替代已确认的海报布局。
- 只换纯色背景或文字颜色并保留排版时，助手优先使用 `recolor_image`。工具按归一化取色点、颜色容差选择连通区域，也支持在明确矩形选区内匹配颜色；可用保护多边形排除商品及边缘，避免背景与商品同色时误选。不调用图片模型，不缩放画布，未选像素及透明度保持原样。高分辨率源图在已有裁切/留边画布上同步换色，保留高清下载。它不是语义背景抠图，复杂场景和不明确范围需要先确认，失败不自动转为整图重绘。
- Agent 可按需保存商品资料和推广方案，生成版本记录对应快照；切换版本会恢复已有记录。上传新商品会重置上个商品的资料与方案。
- 图片接口接收 Agent 组织的本轮完整设计和商品资料，历史标题、配色与排版说明不会自动附加。
- 生成后可通过「原图对照」并排查看，再通过对话提出修改。生成式编辑可能改变商品细节，不能保证与实拍像素一致。

### 生成次数与交付

商品流程默认每轮最多一次生图尝试，生成后直接交付，不自动验图或返工。用户明确要求「生成两张」等数量时才增加本轮次数，仍受 `MAX_IMAGES_PER_TURN` 上限约束；失败的生图尝试也占用次数。

界面无需先选择尺寸或填写方案表单；有指定比例时直接在对话中说明，最终尺寸以图片接口返回为准。画面和所需文字统一由图片模型完成，没有独立文字图层，改字同样属于图片编辑，可能产生模型费用。

## 模型与 API 配置

### 连接真实服务

编辑 `.env`，配置可用的 Key、接口地址和模型 ID，再启动服务。以下模型 ID 与项目示例配置一致，实际可用性由所选服务商决定：

```dotenv
STUDIO_MODE=auto
OPENAI_API_KEY=your-api-key
# 未设置时使用 OpenAI 默认接口；使用兼容服务时填写其 API 基础地址。
# OPENAI_BASE_URL=https://your-provider.example/v1
AGENT_MODEL=gpt-6.1-sol
IMAGE_MODEL=gpt-image-2.5-sunburst
IMAGE_SIZE=auto
```

对话与参考图理解使用 `OPENAI_API_KEY` / `OPENAI_BASE_URL`。如需独立的生图服务，同时设置 `IMAGE_API_KEY` 和 `IMAGE_BASE_URL`；两项都不设置时，生图与编辑复用对话服务。

也可用 `STUDIO_CREDENTIALS_FILE` 指向凭据文件，支持 `~/` 路径。程序只读取其中的 `OPENAI_API_KEY` 和 `OPENAI_BASE_URL`，支持 `export KEY=value` 写法，不执行文件；直接设置的环境变量优先于凭据文件。

| 运行模式 | 行为 |
| --- | --- |
| `STUDIO_MODE=auto` | 有对话 Key 时真实调用，无 Key 时演示；默认值 |
| `STUDIO_MODE=demo` | 强制演示，只绘制明确标注的本地示意图 |
| `STUDIO_MODE=live` | 要求已配置对话 Key，否则启动失败 |

演示模式不进行 AI 理解或真实编辑，演示图片不能作为真实编辑的源图。真实接口失败后，应用会报告错误，不自动切换为演示模式。

### 在界面切换模型

顶部滑杆按钮或侧栏「模型调试」打开配置面板：

1. **中转站**：保存服务名称、API 基础地址、Key 和接口适配器。
2. **模型库**：为中转站登记实际支持的模型 ID，指定「对话」或「生图」用途。也可用「读取列表」请求 `/models`，列表本身不保证模型具备对应能力。
3. **调用路由**：分别选择对话与生图的「中转站 + 模型」。对话负责沟通、参考图理解和工具调用；生图路由同时用于编辑。

真实模式下保存后供后续任务使用，无需重启；有任务执行时禁止修改。编辑 Key 留空会保留原值，更换接口地址需要重新输入 Key。在演示模式中配置好 Key 后，需要重启并使用 `auto` 或 `live` 才会启用真实调用。

首次启动从环境变量或凭据文件初始化。面板保存后，配置写入数据目录中的 `model-settings.json`，文件权限为 `0600`；**已保存配置优先于环境变量**，修改 `.env` 中的初始模型或 Key 不会覆盖面板记录。密钥保存在服务端，不向面板回填，不写入会话记录；Agents SDK tracing 已关闭。

### 接口兼容性与运行参数

内置适配器为 `openai-responses` 和 `openai-chat-completions`。对话接口需要支持函数调用；理解参考图还需要图片输入。生图服务需要兼容 Images API 的生成、multipart 编辑、base64 图片返回，以及 `size`、`quality`、`output_format` 参数。

| 参数 | 说明 |
| --- | --- |
| `PORT` | 本地端口，默认 `4320` |
| `STUDIO_DATA_DIR` | 数据目录，默认项目下的 `.data/` |
| `SKILLS_DIR` | 额外技能目录，与内置及导入的技能一起加载 |
| `IMAGE_SIZE` | 无明确目标或未接入自定义尺寸的模型使用此值，默认 `auto`；GPT Image 2 系列已有目标时按会话的比例与分辨率计算原生请求尺寸 |
| `MAX_IMAGES_PER_TURN` | 每轮图片 API 调用上限；`.env.example` 设置为 `2`，未设置、`0` 或 `unlimited` 表示无全局固定上限；商品流程仍默认一次 |
| `AGENT_MAX_TURNS` | Agent 回合上限；未设置、`0` 或 `unlimited` 表示无固定上限 |
| `TURN_TIMEOUT_MS` | 单轮执行上限，默认 `900000`（15 分钟）；到时限会中止并明确提示「执行超时」 |
| `IMAGE_GRACE_MS` | 到时限时若有生图请求正在执行，先顺延该时长再中止，默认 `300000`（5 分钟），只顺延一次 |
| `TURN_SETTLE_GRACE_MS` | 中止后等待底层请求自行结束的时长，超过则强制收尾并释放会话，默认 `30000`（30 秒） |
| `SANDBOX_MODE` | `local`、`docker` 或 `off`，默认 `local` |
| `SANDBOX_IMAGE` | Docker 镜像，默认 `python:3.12-slim` |
| `SANDBOX_NETWORK` | Docker 网络配置，当前只允许 `none` |
| `SANDBOX_WORKSPACE` | 可选的原生 Docker Sandbox 工作目录根路径 |

任务最长执行 15 分钟（`TURN_TIMEOUT_MS`），到时限后中止并在回复里明确提示「本轮执行超时」，与手动停止区分；若当时生图请求已在执行，会先顺延一次（`IMAGE_GRACE_MS`）再中止。中止后最多等 30 秒（`TURN_SETTLE_GRACE_MS`），底层请求仍未结束则强制收尾并释放会话，不会让会话一直停留在执行中。图片接口禁用 SDK 自动重试。每轮回复下方展示请求的模型、耗时、图片调用次数和服务商返回的 token 用量；遗漏字段保留为未知，已知小计会标注记录不完整。当前未配置费用费率，实际人民币扣费以服务商账单为准。

## 扩展 Skills

### 添加方式

- **项目目录**：在 `skills/` 下添加包含 `SKILL.md` 的技能文件夹。
- **外部目录**：设置 `SKILLS_DIR=/absolute/path/to/my-skills` 后重启服务。
- **本地文件**：在技能库导入单个 `SKILL.md`；有配套参考、脚本或素材时使用完整目录。
- **GitHub 仓库**：在技能库输入公开仓库地址 `https://github.com/org/repo`。服务端浅克隆默认分支，扫描并复制技能到数据目录的 `skills/`，随后删除临时下载目录；导入阶段不执行仓库脚本。

完整目录示例：

```text
my-skills/
  brand-poster/
    SKILL.md
    references/
      brand.md
    assets/
    scripts/
```

`SKILL.md` 示例：

```markdown
---
name: 我的品牌海报
description: 根据品牌规范创建和调整海报
connectors: [openai-images, canvas-artifacts]
---
先读取 references/brand.md，理解品牌规范。
根据用户的用途和画面诉求安排设计。
执行前使用 update_plan 展示简短步骤。
通过 render_image 生成或编辑图片，完成后交付，等待用户后续修改。
```

所选 Skill 随会话保存，每轮加载其指令并记录 ID 和 `SKILL.md` 内容摘要。技能提供创作指南，不授予额外系统权限。商品流程由 `metadata.workflow: product-promotion` 启用，内置入口为 [skills/product-promotion/SKILL.md](skills/product-promotion/SKILL.md)。

### 应用提供的工具

| 工具 | 用途 |
| --- | --- |
| `update_plan` | 展示简短行动清单，不输出内部推理 |
| `read_skill_reference` / `read_skill_references` | 读取当前 Skill 的单份或多份文本参考资料，每轮合计最多 8 份 |
| `render_image` | 调用图片生成或编辑 API，保存新版本及父版本关系 |
| `recolor_image` | 对已有完整图片做颜色选区替换，保持尺寸及未选像素，不调用图片模型 |
| `save_product_brief` | 仅商品流程启用，按需保存商品依据、推广方案和实际文案 |
| `validate_menu_content` | 校验菜单分类、菜名、价格格式、重复项和缺失信息 |
| `render_menu_layout` | 通过 SVG/PNG 确定性排版绘制菜单文字和价格，每轮最多两个版本 |
| `run_skill_script` | 仅声明脚本能力且包含脚本的 Skill 提供，执行需要 Docker 模式 |

菜单设计优先校验数据，再使用确定性排版，交付图片与文字清单供用户核对。可单独提供 `currency`，例如 `currency: ¥` 和 `price: 18` 显示为 `¥18`。

文本参考支持 `.md`、`.txt`、`.json`、`.yaml`、`.yml`、`.csv`，单文件最多 64 KB，限制在所选技能目录的已登记文件内；扫描排除隐藏文件和符号链接。技能摘要只基于 `SKILL.md`，不包含参考文件的内容版本。

Frontmatter 支持 `allowed-tools`、`requires`、`connectors`。声明 `Bash`、`Shell`、`Python` 或 `run_skill_script` 等已识别脚本能力并包含 `scripts/` 时，可启用应用脚本工具；声明本身不会安装依赖。当前已注册 `openai-images` 和 `canvas-artifacts` 连接器，状态可通过 `/api/connectors` 查看。声明 MCP 或未知连接器的 Skill 会显示为未接入，禁止选择。

### 沙箱与脚本

项目通过 Agents SDK 的 `SandboxAgent` 和原生 `skills()` capability 挂载所选技能的指令、参考、素材与脚本。运行方式由 `SANDBOX_MODE` 决定：

| 模式 | 执行环境 |
| --- | --- |
| `local` | 使用 `UnixLocalSandboxClient`，以本机用户权限运行；默认值，适用于可信的本地技能 |
| `docker` | 使用 `DockerSandboxClient`，需要可用的 Docker daemon，容器网络关闭 |
| `off` | 不启用原生 Sandbox，仍可通过应用工具读取技能参考和生成图片 |

应用另提供 `run_skill_script`：只允许当前 Skill 已登记的 `scripts/` 下 Python 或 Shell 脚本，仅在 Docker 模式执行。每次调用使用无网络、无特权、非 root、只读根文件系统的容器，限制为 256 MB 内存、1 CPU 和 30 秒，技能目录只读挂载，工具返回标准输出。依赖的 Python 包或命令必须预装在 `SANDBOX_IMAGE` 中。

上述资源限制属于应用脚本工具，不能据此假定原生 Sandbox 具有相同限制；原生 Docker Sandbox 的资源配额需在 Docker 或外层运行环境设置。第三方 Skill 应先审核内容，再决定是否启用和执行。

## 项目结构与数据

| 路径 | 职责 |
| --- | --- |
| `app/` / `components/` / `lib/` | Next.js App Router、React 工作台、类型与会话/设计状态 |
| `server/web.js` / `proxy.ts` | Next 与 API 同源集成、页面 nonce CSP |
| `public/` | 静态素材、保留的原生界面和模型设置控制器 |
| `server/index.js` / `server/config.js` | 启动参数、环境变量与凭据读取 |
| `server/app.js` | 本地 HTTP API、上传、后台任务、取消与请求去重 |
| `server/agent.js` | Agents SDK Agent/Runner 和创作工具 |
| `server/product.js` / `server/menu.js` | 商品资料与生成约束、菜单校验与排版 |
| `server/adapters.js` / `server/model-settings.js` | 接口适配、模型路由和配置持久化 |
| `server/skills.js` / `server/sandbox.js` / `server/skill-runner.js` | 技能扫描导入、原生挂载与应用脚本执行 |
| `server/store.js` / `server/usage.js` | 会话与图片版本存储、用量记录 |
| `skills/` | 内置技能和按需读取的参考资料 |
| `tests/` | 单元测试、界面测试和可选的付费接口验证 |

默认数据保存在 `.data/`：

```text
.data/
  sessions/           # 会话、消息、任务事件与图片元数据
  images/             # 上传原图与生成版本
  documents/          # 独立设计稿、revision 与完整版本快照
  skills/             # 导入的技能
  model-settings.json # 已保存的服务商、密钥、模型和路由
```

`.env` 和 `.data/` 均已加入 `.gitignore`。备份时保留会话与图片的对应关系，并妥善保管含密钥的模型配置。

会话保存全部消息及各轮附件，每轮向模型传递最近 40 条非错误历史消息及附件、当前选中图片、本轮参考图和版本列表；商品流程另提供商品依据。继续编辑已有结果时可沿用该结果的原始参考图，无需重新附加到输入框。多图生成及编辑使用 Images API 的多图片输入，中转站需支持该接口；不支持时会报告错误，不会静默丢弃参考图。执行记录展示公开工具事件，通过轮询更新，不流式展示模型 token。

这是仅绑定 `127.0.0.1` 的本机单用户应用，提供本地 Host、Origin 和写入令牌检查，页面脚本采用 nonce CSP。Next 通过自定义 Node 服务与现有 Express API 同进程运行，保留长任务及本地文件存储；不能直接作为无状态 Edge/Serverless 或 `output: standalone` 部署。尚无登录、多租户隔离或生产部署配置。当前设计支持属性与画布编辑、窗口内撤销/重做；蒙版重绘、多选和复杂图文的自动排版尚未提供。

新增服务协议时，在 `server/adapters.js` 实现 `createClient`、`modelProvider`、`generate`、`edit`、`listModels` 契约，并将请求的 AbortSignal 继续传给上游；模型与路由配置由 `server/model-settings.js` 管理。
